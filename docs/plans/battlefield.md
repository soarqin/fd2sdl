# 战场系统开发计划

2026-11-04 依据代码基线 `e9a2d81` 与本轮审查重排。本文件维护战场工作包，优先级以 [`development.md`](development.md#4-新优先级与依赖) 为准，所有实现遵守 [`../systems/battle-session.md`](../systems/battle-session.md)。旧 M1～M9 是历史工作编号，不再决定后续开发顺序。

## 1. 当前可用范围与剩余缺口

正式 session 仅开放 **stage 0**。已有新游戏交接、移动／回退、详情页、普通攻击／双击／反击、acted 与 phase、已确认 AI 分支、stage 0 action `0..3`、基础胜负门、系统菜单、活动快照存取与四槽兼容 API。

玩家 magic/item 仍被实现能力门禁用。结束回合、march、部队总览等动作只有分派或确认，没有正式执行后端；F1/Page Up 只有独立辅助状态。四槽 picker 和存储后端有测试，但正式可见触发尚未接入，不能称为完整手工存档 UI。关卡结算、经验升级、FIGANI 和下一关初始化均未完成。

静止菜单位置与开合高亮已按原版机器码修复；局部执行差分通过，不再重复开发。第一关从正式开场持续运行到胜败，以及相应视觉、声音和时序仍为**待原版对照**，允许按[图形自动化测试](../tools/gui-testing.md)在独立副本上自动输入、捕获与比较；既有缺测不会因此自动通过。

### 历史里程碑归档

| 旧编号 | 已有实现 | 未完成事项转入 |
|---|---|---|
| M1～M2 | stage 0 session、交接、光标／镜头、选择框、信息／详情页 | 辅助页和剩余可见效果进入 B1/B7；原版对照进入 V1 |
| M3～M4 | profile 表、地形／占格／控制区、范围、六相位移动和取消回退 | 不重新逆向已确认的基础字段；后续关卡差异进入 B5/B7 |
| M5／M5.5 | phase、stage 0 增援与演出、统一宿主输入 | 必需事件处理进入 B0；输入以逐呈现帧设计为准，不沿用旧 FIFO 方案 |
| M6／M6.5 | 物理攻击、范围／目标、原版菜单资源和坐标／帧选择 | 玩家动作进入 B2/B3，成长进入 B4，原版行为验收进入 V1 |
| M7 | AI 查询／提交、已确认效果、自动 phase、stage 0 结果门 | 结果分派进入 B1；本关出口和下一关进入 B5；特殊 handler 按场景进入 B7 |
| M8 | 系统菜单、活动快照、四槽兼容、配置 bit、返回标题 | 剩余动作与可见入口进入 B1，不再把整个 M8 作为最高优先级重做 |
| M9 | 未实现 FIGANI | B6，与音频 A6 配套 |

逆向事实继续以 canonical 函数登记、格式与源码注释为准，不在计划中保留旧 dual 地址或 wrapper/body 的伪函数结构。单位基础表与新建构造器已实现，不能再将 `0x37/0x39/0x3e` 上游来源列为整个战斗系统的未知前置；**运行中**升级／转职的写入规则仍需单独确认。

## 2. B0：必需事件、提交与失败边界（P0）

**依赖**：现有基线。**目标**：先确保现有支持范围不会在漏执行必需逻辑、日志满或提交后失败时假成功。

范围：

- [ ] 区分诊断信息与必须执行／呈现的事件；统一玩家与自动 phase 的未处理 handler 策略，去除必需逻辑的 `unhandled, skipped` 成功路径。
- [ ] 为 64 项 notice 边界定义明确失败行为；逻辑／演出需要的记录不因日志已满而丢失。
- [ ] 梳理查询、预检、临时移动、效果提交和 common tail 的边界；保留现有 behavior 11 分段提交，不假设外部 RNG 可被 session 浅拷贝回滚。
- [ ] 将必需事件失败、呈现失败、已提交后的未知 cell/stage handler 向正式循环传播；停止后不再执行下一 actor 或进入正常完成出口。
- [ ] 对未确认且会改变玩法的 handler 保持显式拒绝，不退化为物理攻击、待机或空函数。

主要落点：`field_game.c` 的事件记录／phase／动作提交，`field_play.c` 的呈现与终止，相关 `field_event`、`field_ai_commit`、`field_play_result` 测试。只调整需要表达边界的调用链，不全库替换返回码。

验收：

- 玩家事件、AI cell event、演出失败和容量不足均有可复现回归，能定位 stage、actor、action 和发生阶段。
- 查询／取消／预检拒绝不推进 RNG，单位、回合、事件与原文件不变；提交后失败不重试、不假称撤销先前结果。
- 成功事件只提交一次；失败不被 `field_play` 当作正常完成。现有真实 SDL 输入测试、资源和 sanitizer 回归继续通过。

## 3. B1：第一关正式控制与结果分派（P0）

**依赖**：B0。**目标**：受支持的第一关流程可从正式输入到达可区分的终态；不把受限版本称为原版第一关全部功能完成。

### B1.1 结果与应用边界

- [ ] 扩展现有 field/app 返回值，分别传递胜利、失败、游戏内返回标题、宿主关闭和错误；`COMPLETE` 不再吞掉胜败，快速检查也不触发真实结算。
- [ ] 追踪本关结果门及应用级调用者，给当前尚未实现的结算出口明确支持边界；不能仅因没有下一关而静默当成正常返回标题。
- [ ] 新增 victory/defeat／返回标题／宿主关闭／错误的分派测试；把 `main.c` 的枚举转换、静态断言和全部调用者同步更新。

### B1.2 菜单剩余动作与支持范围

| 动作 | 当前状态 | 下一步 |
|---|---|---|
| 活动快照 Save/Load、配置 music/sfx、leave | 正式编排已接入 | 扩充真实输入和故障回归，不重写 codec／播放器；保留未知配置标签与效果限制 |
| 结束回合 | 有确认动作，没有正式执行 | 由原版路径确认后连接现有 phase 能力，验证剩余单位、acted、状态计时、事件与 AI 顺序 |
| march | 有确认动作，没有正式执行 | 确认原版业务含义再接入，不把它猜成结束回合或自动战斗 |
| secondary selector 0 部队总览、F1/Page Up 辅助页 | 有入口分派／状态，未实现真实页面 | 分开维护，各自恢复关闭键、分页与返回路径；不能共用空白辅助状态冒充完成 |
| 四槽手工 Save/Load | codec、picker、事务 API 和正式循环处理分支已有 | 确认 `field_manual_slot_dispatch @0x29300` 的可见调用入口后连接，不能替换 secondary 的活动快照路径 |

- [ ] 正式 UI 中未实现的动作不能确认后仅打印 pending 并看似成功。开发版本若按实现能力禁用，必须说明这是 SDL 限制，不登记为原版禁用规则。
- [ ] 补充 Save → 改变状态 → Load → 继续行动的真实 SDL 输入回归，验证恢复清理临时状态并应用配置；失败不改当前 session 或原档。
- [ ] 覆盖无文件、坏 checksum、无效／空 slot、单位容量边界、尚不支持的 stage 和宿主关闭。

验收：支持的菜单动作都从正式键盘路径到达；结束回合实际推进 phase；胜败不会混同。march、辅助页或手工槽入口缺原版证据时单独标阻塞，**不阻止已具备动作契约的 B2/B3 开发**，但阻止将第一关整体标为原版验收通过。

人工证据：菜单各页和确认结果、已行动后的存档门、四槽入口、结束回合，以及胜／败／离场的可见去向。所有操作由开发者手工完成，不自动操作 DOSBox。

## 4. B2：玩家法术（P1）

**依赖**：B0 与 B1 的动作／结果契约，不依赖全部辅助页。原版入口：`field_player_magic_command_execute @0x1cff0`。

范围：

- [ ] 确认玩家法术列表、可用性／状态门、施法中心、目标阵营与范围、取消返回路径。
- [ ] 明确 MP 扣除和 acted 时点，区分施法成功、无目标、命中失败与特殊 handler；不从 AI 的 MP 门推断玩家消费规则。
- [ ] 复用已确认魔法表、范围与 effect 核心；独立实现玩家选择和收尾，不调用 AI 评分器来代替玩家目标选择。
- [ ] 先开放有完整证据的分支；IDs `23/24、28..35` 等未支持 handler 仍显式隔离。若当前场景必需，提升为本工作包前置，而非永久留在 B7。

验收：正式菜单可进入列表并完成至少一项伤害和一项恢复／状态动作的已确认路径；覆盖不足 MP、禁止状态、空列表、非法目标、多目标顺序、逐级取消、重复确认、死亡与胜败门。逐目标 RNG 次数、MP、acted 和库存写入逐项断言；这些分支缺证据时不能用近似值补齐。

## 5. B3：玩家物品与已确认库存操作（P1）

**依赖**：B0 与 B1 的动作／结果契约；默认在 B2 后复用实际形成的范围／选择能力。原版入口：`field_player_item_command_execute @0x1bbdc`。

范围：

- [ ] 恢复物品列表、空槽／装备标志、目标选择和取消；使用、装备或其他操作是否属于该入口，逐调用分支确认，不按现代 RPG 惯例添加功能。
- [ ] 将已确认的恢复／伤害等 effect 连接到玩家路径，明确每类 code 是否消耗、何时压紧 slot，以及末槽 stale item ID 的保留规则。
- [ ] 在状态或装备变化后只重算必要派生字段，不重建整条单位记录，不覆盖未知字段。

验收：覆盖消耗与非消耗路径、满 HP、无目标、取消、最后／中间槽、未知 code、派生重算和 acted；效果及库存只提交一次，失败前后的未知字节保持原样。AI 已通过的 item code 不自动视为玩家路径已验收。

## 6. B4：经验、升级与持续单位状态（P1）

**依赖**：B0 的动作提交／奖励边界。公式和字段研究可先行，默认在 B2/B3 后统一接入已开放的玩家指令，不以辅助页或未开放能力为阻塞。

- [ ] 从原版动作／结果调用者确认经验归属、奖励时点、升级阈值、成长与字段宽度；不使用角色创建的等级公式直接替代运行中升级。
- [ ] 明确 HP/MP 上限变化时当前值如何处理、派生重算顺序、装备影响和一次动作多次升级等实际存在的分支。
- [ ] 将已确认持续状态连接到 Save/Load，逐字保留无关字段；转职、特殊状态变更仅在有入口与证据时启用。

验收：动作前后经验、等级、HP/MP、派生值和 RNG 均有断言；边界／封顶行为按原版证据测试。存档往返不丢成长和装备，取消或无结算路径不得重复获奖。

## 7. B5：第一关结算到下一关（P1）

**依赖**：B1、B4；场景音乐使用 A5。先做 stage 0 → stage 1 的一个完整流程，不一次解除所有 stage 限制。

- [ ] 确认 stage 0 专用结束 callback、胜败剧情、奖励／持续状态、资源值和转场顺序；不把原版剧情退出标志直接当通用输赢。
- [ ] 明确哪些单位跨关保留、哪些来自下一关 metadata／placement、哪些状态重置，以及 cache／事件／镜头／音频重建时点。
- [ ] 准备并验证下一关 session 后切换 owner；失败不留下半个新关卡，不破坏原文件。
- [ ] 同步扩展受支持 stage 的活动快照与手工槽恢复。runtime 64、活动快照格式 96、手工槽 32 的边界分别处理，禁止截断。
- [ ] 以对应关卡的完整 handler 集作为开放条件；不能用其他 stage 的通用全灭判断冒充私有结果脚本。

验收：从标题新游戏经第一关到达真实下一关；胜利、失败、离场和出错分支可区分；下一关 Save/Load、资源释放和重复进入均通过。第一关关键流程、结果和转场仍需 DOSBox 原版证据，自动捕获也须有已确认判据，缺失时不标整段通过。

## 8. B6：FIGANI 战斗演出（P2）

**依赖**：B0/B1 的提交／场景契约及对应效果，法术演出复用 B2 已开放的逻辑。默认排在 B5 后，但不以 stage 1 初始化完成为技术前置；数字音效动态 bank 由 A6 配套。

- [ ] 安全验证 FIGANI 的 408 个归档条目；容器条目数通过不等于动画语义已实现。
- [ ] 确认单位／动作／entry、背景、调色板、帧序和 effect/cue 触发点。原版动画内调用的结算必须与逻辑层拆清，不能重复扣血。
- [ ] 在地图状态与确定性结算之上呈现攻击、受击和施法；跳过与完整播放共享同一已确定结果。
- [ ] 将不支持的纯演出模式与损坏资源严格区分；坏数据不能一律静默退回无演出。

验收：完整播放、跳过、静音、null 音频和关闭窗口下的业务结果／RNG 次数不受演出重复执行影响；解析、设备和提交后失败分别测试。至少一组攻击／受击／施法的帧序、声音与 DOSBox 原版捕获对照。

## 9. B7：按场景扩展的剩余能力（P2，必经项随时前移）

- 后续 stage 的专用剧情／cell handler、特殊 AI behavior、特殊法术／物品、转职与复活等，按实际场景和调用者逐项确认，不先造一个通用大解释器。
- B1 中未阻塞主流程的部队总览、战术缩略图、G 键和其他辅助操作；原版用户可见名称、分页和关闭规则仍按原版捕获证据落实。
- 后两项配置效果及剩余战场 SFX；已有 bit 持久化不能算作可见效果完成。
- 更多关卡的单位／事件／存档恢复；每关有资源、初始化、handler 和结果流程证据后再开放。

进入当前场景必经路径的项目，不得继续以 B7 低优先级为理由跳过。

## 10. 测试与原版证据

沿用 [`../tools/README.md`](../tools/README.md) 的构建、CTest、Python、sanitizer 和快速检查命令。测试分层不能混用：

| 层 | 主要证明 | 不能替代 |
|---|---|---|
| 纯逻辑／合成资源 | 边界、状态变化、RNG、原子提交和错误处理 | 正式输入路径、原版玩法／视觉 |
| 本地原版资源兼容 | 当前资源和存档格式可解析，未知字节保持 | 全部 opcode、所有关卡或互操作行为 |
| `*-once` 集成检查 | 资源加载、共享逻辑和快速回归 | 用户真正走过输入状态机 |
| Windows 原生键盘／Linux Xvfb/XTest 正式输入 | SDL 循环的菜单、移动、攻击及新增动作可达；截图留存窗口结果 | DOSBox 语义或硬件时序 |
| 原版机器码差分 | 明确列出的函数／分支计算一致 | 完整游戏、全屏合成、声音或设备行为 |
| DOSBox 独立副本自动输入／捕获与比对 | 按已确认判据验证对应场景的可见结果、时序和声音 | 未覆盖分支的整体正确性；仅无人值守运行不算行为通过 |

下一批原版自动比对证据优先收集第一关菜单／结束回合、Save/Load 与胜败出口，再按 B2/B3 收集法术与物品样例。每项记录 stage、输入步骤、期望结果、资源／存档身份和未覆盖分支。原版文件、截图和 dump 留在本地，不随 Git 提交。
