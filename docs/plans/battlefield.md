# 战场系统开发计划

2026-11-04 依据代码基线 `e9a2d81` 与本轮审查重排。本文件维护战场工作包，优先级以 [`development.md`](development.md#4-新优先级与依赖) 为准，所有实现遵守 [`../systems/battle-session.md`](../systems/battle-session.md)。旧 M1～M9 是历史工作编号，不再决定后续开发顺序。

## 1. 当前可用范围与剩余缺口

正式 session 仅开放 **stage 0**。已有新游戏交接、移动／回退、详情页、普通攻击／双击／反击、acted 与 phase、已确认 AI 分支、stage 0 action `0..3`、基础胜负门、系统菜单、活动快照存取与四槽兼容 API。

玩家 magic/item 仍被实现能力门禁用。结束回合已连接 phase 后端，胜／败与游戏内离场、宿主关闭、错误分别传递。stage 0 战况总览接入只读弹窗；march 和后两项设置按 SDL 实现能力禁用，F1/Page Up 留在浏览态并报告未实现。四槽 picker 和存储后端有测试，但正式可见触发尚未接入，不能称为完整手工存档 UI。关卡结算、经验升级、FIGANI 和下一关初始化均未完成。

静止菜单位置与开合高亮已按原版机器码修复；局部执行差分通过，不再重复开发。第一关从正式开场持续运行到胜败，以及相应视觉、声音和时序仍为**待原版对照**，允许按[图形自动化测试](../tools/gui-testing.md)在独立副本上自动输入、捕获与比较；既有缺测不会因此自动通过。

## 2. B0：必需事件、提交与失败边界（P0）

**依赖**：现有基线。**目标**：先确保现有支持范围不会在漏执行必需逻辑、日志满或提交后失败时假成功。

范围：

- [x] 区分诊断信息与必须执行／呈现的事件；统一玩家与自动 phase 的未处理 handler 策略，去除必需逻辑的 `unhandled, skipped` 成功路径。
- [x] 为 64 项 notice 边界定义明确失败行为；逻辑／演出需要的记录不因日志已满而丢失。
- [x] 梳理当前已支持动作的查询、预检、临时移动、效果提交和 common tail 边界；保留 behavior 11 分段提交，不以 session 浅拷贝伪造外部 RNG 回滚。
- [x] 将必需事件失败、呈现失败、已提交后的未知 cell handler 向正式循环传播；停止后不再执行下一 actor 或进入正常完成出口。正式 session 仍仅开放 stage 0，不以通用结果门开放其他 stage。
- [x] 对未确认且会改变玩法的 handler 保持显式拒绝，不退化为物理攻击、待机或空函数。

主要落点：`field_game.c` 的事件记录／phase／动作提交，`field_play.c` 的呈现与终止，相关 `field_event`、`field_ai_commit`、`field_play_result` 测试。只调整需要表达边界的调用链，不全库替换返回码。

当前实现用 session 首错状态停止流程，在执行 handler 前检查 notice 容量；演出成功后确认一次。已提交后的错误保留效果与 RNG，停止状态不能保存，有效加载可恢复。自动回归覆盖玩家、AI、容量、后续事件／状态计时、提交后失败不重试和存档恢复边界；这是 SDL 错误处理验收，不等于对应原版玩法已经全部对照。

验收：

- 玩家事件、AI cell event、演出失败和容量不足均有可复现回归，能定位 stage、actor、action 和发生阶段。
- 查询／取消／预检拒绝不推进 RNG，单位、回合、事件与原文件不变；提交后失败不重试、不假称撤销先前结果。
- 成功事件只提交一次；失败不被 `field_play` 当作正常完成。当前平台适用的真实 SDL 输入和资源回归继续通过；sanitizer 等其他平台专用检查保留条件与历史记录，不作为当前平台的验收前置。

## 3. B1：第一关正式控制与结果分派（P0）

**依赖**：B0。**目标**：受支持的第一关流程可从正式输入到达可区分的终态；不把受限版本称为原版第一关全部功能完成。

本轮按以下边界推进并独立提交：

| 小阶段 | 交付与关闭条件 | 当前边界 |
|---|---|---|
| B1.1 | 独立胜／败、游戏内离场、宿主关闭与错误分派；全部调用者和回归同步 | 已提交 `542aeb6`；旧返回标题建模在 B1.3b 按原版纠正，不包含结算 |
| B1.2a | 原版持久玩家构造、装备／法术初值与精确写集 | 已提交 `2148632`；32 个角色回归与独立只读复核通过 |
| B1.2b | 受支持菜单、END、活动快照 metadata、独立 roster 与恢复后行动；错误／取消无副作用 | 本轮修复首次保存、坏档保护、容量边界、整表 owner 和招募回滚；窗口配对另见 B1.3 |
| B1.3a | 原版与 SDL 肯定 END 一次，识别新回合、原始焦点，再从正式菜单 Save；比较已确认且不受随机流影响的字段 | 真实 START 的配对通过；修复 SDL 新回合未返回 actor 0 的焦点／镜头 |
| B1.3b | 原版 Save/Load 与离场核心配对证据 | Load 配对已提交；离场实机与修复后 SDL 均自然退出，取消／错误另有回归；不覆盖全部对话视觉和声音 |
| B1.4a | 原版字形背景、阴影与裁切 | 已按静态指令修复并补内存回归；受影响菜单 WGC 继续通过，完整字形 ROI 留待 B1.4b |
| B1.4b | 战况与胜败条件总览 | b1 纯绘制、b2 开合／任意键关闭已实现；START 四静态区、只读状态与宿主关闭原版 WGC 配对通过，整套17组继续通过 |
| B1.4c～e | 批量行军、F1 辅助页、四槽可见入口及关卡重建 | 各自仍有限制；按既有依赖允许 B2/B3 先行，但不能记为 B1 全部完成 |

**B1 大阶段当前仍为部分完成。** 关闭时须逐项核对上表支持范围和原版证据，再做整段审查、问题修复与冗余精简，运行必要回归并提交；当前已实现子阶段的审查不冒充大阶段终审。整关胜败剧情／结算属于 B5，完整玩法、声音和时序属于 V1 的对应场景，不因 B1 核心合同通过而自动验收。

每个小阶段验证后独立提交并记录哈希、证据和未覆盖范围，随后继续下一项。遇到阻塞可调整计划，但须记录依据、转移后的任务及验收条件；没有明显更优的业务方案时再请求用户选择。

2026-11-04 的行军前置复核推翻了「AI 路径不查沿途格事件」和「玩家逐格执行 handler」的旧假设。`@0x13488` 共享播放器每步只以 match0 更新单个 pending，未命中保留旧值，完整路径后才由调用者分派；玩家和AI的 acted／phase／dispatch 顺序不同。B1.4c 因此拆为 c1a 修复AI的共享pending、c1b修复玩家完整动作与取消／后置顺序、c2接入批量行军。每段分别验证提交；旧即时处理测试不再充当原版oracle。行军入口在这些前置收口前继续禁用，未把已确认差异隐藏为后续玩法扩展。

- [x] 正式 UI 按 SDL 实现能力禁用未实现动作，移除确认后仅打印 pending 的假成功；不登记为原版禁用规则。
- [x] 补充 Save → 改变状态／配置 → Load → 继续行动的真实 SDL 输入回归；恢复清理临时状态并应用配置。

结束回合依据 `field_empty_focus_menu_execute @0x16f55` 与 `field_turn_cycle_run @0x1a30b`：不先统一标记剩余玩家 acted；仅对 side 2、`flags & 0x81 == 0`、record `+0x25/+0x26` 为零且 `HP != maxHP` 的单位增加 `maxHP/5`、封顶并置 acted。整数恢复为零也置 acted；之后沿用事件、状态计时和自动 phase 流程。显式快速跳过 helper 与正式 END 分离。

原版自动探测另发现标题行为映射错误：三项标题的 `START/LOAD/CONTINUE` 分别为新游戏／手工槽／活动快照。SDL 改用 CONTINUE 恢复活动快照；尚未实现的手工 LOAD 明确提示并留在标题。标题像素一致本身不证明点选行为一致。

共用确认框按原版 `sub_19953 @0x19953` 修正为默认左侧 YES、右侧 NO，上下不改变选择；复用 FDOTHER[2] 的 ID 16/17，在 `(232,168)/(264,168)` 显示按钮。确认、拒绝或取消后退出菜单回浏览，存档成功后不重新打开 secondary。原版该框的头像眨眼调用共享 RNG；本轮不以固定 SDL seed 冒充相同原版随机初态，整回合伤害一致仍需独立随机流证据。

原版 Continue 暴露了活动快照的另一处错误：旧实现保留全部文件前缀，却只把 stage 改成 0，导致保留的 stage 29 metadata 首字节 `0x1d` 让原版选择错误 FDSHAP。活动快照现携带 `0x8a3` metadata 区及其后的独立持久 roster；session 写回本关 metadata 有效前缀（stage 0 为 937 字节），保留目标容器的 metadata 未用尾；完整 roster 则随 session 恢复并整表写回。加载检查 shape 契约并准备本关模板及独立 roster 后原子交接；无效输入不改变 session。不能把底图错误归因于旧 `FD2.TMP`：原版恢复会从 FDICON 重建并覆盖该缓存。

真实 `START.SAV` 的活动数量为 12、roster 为 4，本地后期档为 27／31，推翻了先前「count 副本」假设。B1.2 将该独立 owner、原版持久角色构造与 stage 0 已确认招募纳入修复；手工 Load 的活动快照假实现收回，留待 B1.4 的关卡重建契约。原版 END 和 Save 对照优先使用只读复制的真实 START，不能仅靠 SDL 自产夹具证明格式互操作。

验收：支持的菜单动作都从正式键盘路径到达；结束回合实际推进 phase；胜败不会混同。march、辅助页或手工槽入口缺原版证据时单独标阻塞，**不阻止已具备动作契约的 B2/B3 开发**，但阻止将第一关整体标为原版验收通过。

原版证据：菜单各页和确认结果、已行动后的存档门、四槽入口、结束回合，以及胜／败／离场的可见去向。允许自动操作 DOSBox 独立副本；每一步须验证已到达的状态，保留截图／存档／trace 与比对结果，不向 `original_game/` 写入。

## 4. B2：玩家法术（P1）

**依赖**：B0 与 B1 的动作／结果契约，不依赖全部辅助页。原版入口：`field_player_magic_command_execute @0x1cff0`。

## 10. 测试与原版证据

沿用 [`../tools/README.md`](../tools/README.md) 的构建、CTest、Python、sanitizer 和快速检查命令。测试分层不能混用：

| 层 | 主要证明 | 不能替代 |
|---|---|---|
| 纯逻辑／合成资源 | 边界、状态变化、RNG、原子提交和错误处理 | 正式输入路径、原版玩法／视觉 |
| 本地原版资源兼容 | 当前资源和存档格式可解析，未知字节保持 | 全部 opcode、所有关卡或互操作行为 |
| `*-once` 集成检查 | 资源加载、共享逻辑和快速回归 | 用户真正走过输入状态机 |
| Windows 原生键盘／Linux Xvfb/XTest 正式输入 | SDL 循环的菜单、移动、攻击及新增动作可达；截图留存窗口结果 | DOSBox 语义或硬件时序 |
| 原版机器码差分 | 明确列出的函数／分支计算一致 | 完整游戏、全屏合成、声音或设备行为 |
| DOSBox 独立副本自动输入／捕获与比对 | 按已确认判据验证对应场景的可见结果、时序和声音 | 未覆盖分支的整体正确性；仅无人值守运行不算行为通过 |

下一批原版自动比对证据优先收集第一关菜单／结束回合、Save/Load 与胜败出口，再按 B2/B3 收集法术与物品样例。每项记录 stage、输入步骤、期望结果、资源／存档身份和未覆盖分支。原版文件、截图和 dump 留在本地，不随 Git 提交。
