# C 阶段：运行时配置、键位与手柄、引导配置界面

**C0–C6 已完成，版本为 v0.2.0。** 基线为 `6b32c89`。玩家现在可以在启动前配置画面、声音、路径、键位、手柄和节奏。C3b 的经验和金钱倍率仍待单独确认。操作方法见[使用指南](../user-guide.md#启动设置)，本次验证范围见[执行记录](#9-执行记录)。

## 1. 目标与边界

| 编号 | 目标 | 本阶段交付 |
|---|---|---|
| C-1 | 硬编码值改为配置项 | 盘点可调的硬编码值，按影响分级；可调项集中到一张设置表，从配置文件读取，带默认值、范围检查和回退 |
| C-2 | 键位可配置，支持手柄 | 新增「物理输入 → 原版虚拟键」重映射层，加入 SDL 手柄输入；FIFO、重复和修饰键语义不变 |
| C-3 | 一致性声明 | 从本阶段首个版本起声明：**只有在默认配置下，游戏逻辑才与原版一致** |
| C-4 | 引导配置界面 | 参照 sdlpal 的启动配置窗口，用 SDL3 实现一个独立于游戏画面的配置界面 |

不在本阶段范围内：

- 游戏内选项页、热键菜单，以及任何改变原版菜单结构的改动。原有的四个存档选项（音乐、音效、FULL／SHORT、信息板）照旧在游戏内调整。
- 改变存档格式。配置不写进 `FD2.SAV`，存档与原版双向兼容。
- 用配置项重复 `data/static/` 已有的构建期 Mod 能力（物品、单位、法术、商店、流程表等）。
- 鼠标操作游戏。只有引导界面支持鼠标。

## 2. 硬编码值盘点与分级

### 2.1 分级规则

每个配置项归入一类，第 4 节的一致性声明据此判定：

| 等级 | 含义 | 对一致性的影响 |
|---|---|---|
| **H 宿主** | 只改变画面呈现、声音输出设备／音量、文件位置或物理输入来源；游戏收到的输入码、时钟、RNG 和规则都不变 | 任意取值都不影响一致性 |
| **P 节奏** | 改变等待、动画或按键重复的时间。原版的等待中，头像眨眼会按时钟消耗共享 RNG，所以节奏项也会改变后续战斗结果 | 非默认即偏离原版 |
| **R 规则** | 直接改变数值结果（经验、金钱、命中等） | 非默认即偏离原版 |

## 3. 键位与手柄

### 3.1 重映射位置

现有链路为：SDL 事件 → `key_transition`（`input.c:302`）→ `bios_key` 生成 AX → 15 项 FIFO。新的映射层插在 `key_transition` 之前，把物理输入转换为「原版虚拟键」（仍以 SDL scancode 表示），之后的 `previous_down`、单键重复、修饰键、PrintScreen／fake Shift 和 FIFO 全部沿用。这样：

- 默认恒等映射下，任何输入产生的 AX 与现在逐字节相同，现有输入回归无需修改期望值。
- 不新建第二个输入 owner 或队列，符合[输入合同](../systems/input.md) §5。
- `sample_key_state`（`input.c:366-376`）按虚拟键对比状态；测试注入的 `fd2_input_set_test_key_state` 路径保持按 SDL scancode 工作。

### 3.2 键盘绑定规则

- 绑定的对象是原版虚拟键：Up、Down、Left、Right、Enter、Space、Esc、Delete、Insert、Home、PageUp、F1、F2、G、Z、Keypad5，以及各 F 键。
- 每个虚拟键可绑定多个物理键。**出现在绑定里的物理键改为产生对应虚拟键；没出现的物理键原样透传。** 这样准备页隐藏入口（Shift／Ctrl／Alt+F 键按原始 AH 比较）和数字小键盘别名默认仍然可用。
- 修饰键本身不可重绑，按物理状态参与 AX 计算。允许把单个物理键绑定为组合，例如 `Shift+F1`；组合的修饰位按现有 F13 fake Shift 方式产生。
- 多个物理源同时按住同一虚拟键时按引用计数处理，最后一个源松开才产生虚拟 UP。
- 配置示例：

```ini
[keyboard]
Enter = Return, Space, J
Esc = Escape, K
F2 = Home, L
```

### 3.3 手柄

- 初始化增加 `SDL_INIT_GAMEPAD`，支持热插拔；同一时间只取第一个已连接手柄。
- 手柄按键和摇杆被转换成虚拟键 DOWN／UP，送进与键盘相同的映射点。因此长按同样按 500／33 ms 重复，同样受 15 项队列限制，焦点丢失同样清空。
- 左摇杆按主轴量化为四方向，带死区（默认 50%）和回差，避免斜推同时产生两个方向键；D-pad 与摇杆按 3.2 的引用计数合并。
- 拔出手柄时，为它按住的虚拟键补发 UP，不会留下卡住的重复。
- 保持 SDL 默认行为：窗口失焦时不接收手柄事件。
- 默认绑定（可在配置文件和引导界面修改）：

| 手柄 | 虚拟键 | 游戏中的作用 |
|---|---|---|
| D-pad／左摇杆 | Up／Down／Left／Right | 移动光标、选择 |
| South（A） | Enter | 确认 |
| East（B） | Esc | 取消／返回 |
| West（X） | F2 | 单位详情 |
| North（Y） | F1 | 全场地图 |
| LB／RB | Z | 轮换焦点 |
| Back | G | 原版 G 键 |
| Start | Space | 确认（标题 AL 0x20） |

## 4. 一致性声明

从本阶段首个提交起，项目对外声明改为：

> 自 v0.2.0 起，**只有在默认配置下**，SDL 版的游戏逻辑才与原版一致。默认配置指：没有配置文件，或所有 P 节奏、R 规则项都取默认值。H 宿主项（窗口、音量、路径、键位、手柄）取任意值都不影响一致性。修改 P 或 R 项后的行为，不在原版一致性承诺内。已登记的例外（Nuked OPL3 音色与响度）不变。

落实方式：

1. **版本号**：`CMakeLists.txt` 的 `project()` 加 `VERSION 0.2.0`，生成版本头供程序和引导界面显示。项目此前没有版本号或 tag，`0.2.0` 是建议值，正式起用前可改。
2. **运行时判定**：设置表的每一项带 H／P／R 等级。程序启动后计算「当前是否为一致配置」，写入启动日志。非默认时，窗口标题加后缀「（非原版设置）」；引导界面实时显示同样的状态。
3. **文档**：在 README、[使用指南](../user-guide.md)、[文档索引](../README.md)和 [AGENTS](../../AGENTS.md)中写入上述声明，并说明各配置项的等级。
4. **测试隔离**：CTest 统一设置 `FD2SDL_CONFIG=none`，原版对照工具同样传 `--no-config`，确保开发者本机的配置文件不会进入回归。对照收据记录实际使用的配置身份（`none`，或配置文件的路径与 SHA256）。

## 5. 配置文件

- **格式**：参照 sdlpal 的 `key=value`，加 `[分组]` 节，`#` 开头为注释，键名不区分大小写。程序内用一张 C 设置表（键名、类型、默认值、范围、H／P／R 等级、界面标签）统一驱动解析、校验、写回和引导界面，类似 sdlpal 的 `gConfigItems`。
- **查找顺序**（找到即停）：
  1. 命令行 `--config <路径>`；`--no-config` 表示全用默认值，不读也不写。
  2. 环境变量 `FD2SDL_CONFIG`（值为 `none` 时等同 `--no-config`）。
  3. 工作目录下的 `fd2sdl.cfg`（与 `original_game/` 同级，便携）。
  4. `SDL_GetPrefPath` 目录下的 `fd2sdl.cfg`。
- **优先级**：命令行 > 环境变量（如 `FD2SDL_SAVE_PATH`）> 配置文件 > 默认值。
- **容错**：越界值钳到范围内并警告；无法识别的值回退默认值；未知键原样保留，写回时不丢失；文件损坏不阻止启动。
- **写入**：先写临时文件再原子替换。写入目标经符号链接和 junction 解析后，不得落在原版资源目录内。

## 6. 引导配置界面

### 6.1 参照 sdlpal 的行为

sdlpal 首次运行时弹出配置窗口（`LaunchSetting` 默认开启），分为游戏目录、语言字体、日志、显示和音频几组，底部有「退出／启动游戏／恢复默认」三个按钮。「启动游戏」保存 `sdlpal.cfg`、清除首次运行标记，然后在同一进程内继续启动游戏。sdlpal 在 Windows 和 Linux 分别用 Win32 对话框和 FLTK 实现，macOS 没有这个界面。

### 6.2 本项目的做法

- **实现**：用 SDL3 自绘，三个平台同一套代码，不引入 FLTK 或平台原生对话框。界面运行在游戏窗口创建之前的独立窗口里；关闭后再按新配置创建游戏窗口，并初始化音频和资源。
- **何时出现**：
  - 找不到配置文件，即首次运行；
  - 命令行 `--setup`；
  - 配置项 `[launcher] show_on_start = on`。

  `--no-config`、开发和测试用的启动模式（`--field-play` 等）不会弹出界面，除非显式加 `--setup`。
- **页面**：

| 页 | 内容 |
|---|---|
| 路径 | 游戏数据目录（实时检查所需原版文件是否齐全）、存档路径 |
| 画面 | 缩放倍数、全屏、缩放模式、滤镜、4:3 校正 |
| 声音 | 音量、静音、输出设备（列出 SDL 枚举到的设备），以及「试听」按钮 |
| 键盘 | 每个虚拟键列出已绑定的物理键；点击后按键录入；可一键恢复默认 |
| 手柄 | 显示已连接的手柄，按键录入，调死区，实时显示摇杆位置 |
| 节奏与规则 | P／R 项，每项标出「改变后与原版不一致」 |

- **按钮**：启动游戏（保存并启动）、仅保存、恢复默认、退出（不保存）。界面顶部常驻当前版本号和「原版一致／非原版设置」状态。
- **操作方式**：引导界面支持键盘、鼠标和手柄。这些操作只作用于界面本身，不进入游戏输入队列。
- **文字渲染**：`FDOTHER[4]` 含 1,824 个游戏字形。经核对，「窗、屏、键、柄、设、声、画」等界面常用字都不在其中，所以不能直接用原版字库。建议在构建期从开源 16×16 点阵字体（首选 GNU Unifont，GPLv2+ 字体例外／OFL-1.1 双许可，接入前再核实）裁出界面实际用到的字，生成 `.inc` 内嵌，并补充第三方声明和许可文件。界面文字固定为简体中文，加英文回退；有字缺失时构建失败。

## 7. 分阶段实施

每个小阶段验证后单独提交，然后继续下一阶段；全部完成后做一次整体审查、修复和精简，再运行完整保留回归。

| 小阶段 | 交付 | 验证 |
|---|---|---|
| **C0 声明与版本** | 版本号、一致性声明进入文档；CTest 和对照工具强制无配置 | `ctest -N` 注册不变；全部测试在 `FD2SDL_CONFIG=none` 下运行 |
| **C1 设置框架** | 设置表、解析和写回、查找顺序、命令行与环境变量优先级、一致性判定和日志；34 处原版路径统一成一个资源根 | 新的 `settings` 单元测试覆盖解析、钳制、未知键保留、原子写入、原版目录拒写和优先级；默认配置下现有回归不变 |
| **C2 宿主项接入** | 画面、音量、静音、设备和路径接入 | 默认值下截图和 PCM 捕获与 C1 相同；非默认的窗口和缩放用 WGC 定向截图检查 |
| **C3 节奏项接入** | 按键重复、文字速度、动画速度、新游戏选项初值 | 默认值下 RNG、等待和存档回归不变；非默认取值的定向回归确认生效，并确认 H／P 判定和标题后缀正确 |
| **C4 键位重映射** | 映射层、透传、组合绑定、引用计数 | `input` 回归默认期望不变；新增重绑、透传、隐藏入口组合、双源按住、焦点丢失用例；Windows 后台按键驱动在自定义绑定下跑一条定向用例 |
| **C5 手柄** | 手柄初始化、热插拔、按键和摇杆量化、拔出释放 | 用 SDL 虚拟手柄（`SDL_AttachVirtualJoystick`）做无硬件回归，覆盖重复、队列上限、死区回差、拔出补 UP；实体手柄手动检查单独登记 |
| **C6 引导界面** | 界面、触发条件、各页、按键录入、字体子集生成 | 首次运行、`--setup`、`--no-config` 三种触发的定向测试；WGC 截图检查各页；保存后重启读回一致；退出不写文件 |
| **C3b 规则项（可选）** | `exp_rate`、`gold_rate` | 需单独确认后再做；默认值回归不变，非默认值覆盖上限与溢出 |
| **收尾** | 整体审查、修复、精简；更新使用指南（配置文件、键位、手柄、引导界面）和工具文档 | 当前平台完整保留回归；未执行的平台和原版对照如实标注为待验 |

## 8. 风险与待确认

| 项 | 说明 | 建议 |
|---|---|---|
| 版本号取值 | 项目此前没有版本号 | 采用 `0.2.0`，可改 |
| 界面字体 | 原版字库不够用，需要引入第三方点阵字体 | 采用 Unifont 构建期子集；如不想引入新的第三方组件，可改为纯英文界面（SDL3 自带 8×8 调试字体） |
