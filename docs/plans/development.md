正常有效域、原程序未定义域和宿主适配域继续按 [A01—A22 矩阵](full-alignment-audit.md#1-终态参照与有效域)分别登记。不能以拒绝／禁用缩小正常玩法，不无限模拟任意内存破坏。冷定义仍以 `data/static/` 为唯一输入，沿用单一热状态、Game／Scene／App owner、RNG 和 SAV 提交边界。

## 5. F6：联合审查、修复精简与最终验收

**矩阵 A21 及全部 A01—A22 的表现层结论；依赖 F1—F5 主体及 DOS-CLEAN 完成，QK 游戏行为问题须在最终门前闭合。完整 F6 为一个提交单元。**

先审查每个残余是否存在具体游戏影响。纯 ABI／原栈／CPU／PIT／IRQ／绝对首相位／完整 BSS 形式项归历史或可选研究，移出必做清单；若会影响掉落、经验、AI、去向、存档、输入、RNG、画面或声音，则列出具体结果、合法场景和最小独立对照。

保留并完成：QK 三类条件 consumer；F3 后期状态和败北重开／存取链；F4 正常目标、MP、禁 Save 和 END→Save 后缀及未解释像素；完整正常输入／等待／共享 RNG 导致的游戏结果；F5 正常音乐音效、切景和音画同步。按共享机制／数据族批量覆盖，不逐关开发，不重复原有静态或 GUI 批次填进度。

集中审查全部共享实现和历史功能，运行当前 Windows 适用的完整逻辑／输入及正式游戏代表。证据可按源码、资源、语义和反馈的实际依赖继承；必须重跑的只列真实失效原因。修复后测直接影响，再执行最终联合门；不得混合候选、把 skip／未注册当通过。

最终完成门：

1. A01—A22 逐项给出正常域、实现身份、独立来源和表现层结论。纯研究标「不再要求」，不是「通过」；真实游戏未知和必需缺证仍会阻塞完成。
2. 资源、分派、绑定、语义族、关卡／入口与结局分母闭合。一次共用机制证据可覆盖有明确包含关系的绑定，重复引用不作功能率。
3. 正式 START／CONTINUE／LOAD、战斗／准备／隐藏与结局及失败／取消／重载的游戏状态、存档和 owner 合同通过。QK／后期状态／败北重开相关后续行为有充分独立证据，不能只看一帧或未崩溃。
4. 输入响应、等待／动画／音乐节奏、共享 RNG 结果、画面与非例外声音一致。以源内容、正常原版表现及重复观测确定比较方法，测量噪声单列；不随意加宽容差，也不反向要求 CPU／硬件形式一致。
5. 正常可达的原版 U 边界逐项说明有效前缀及影响，H 适配不侵入正常玩法。未知字段仅在会被游戏消费时追来源；不复制无表现意义的内存错误。
6. Windows 实际适用检查、WGC／owned 输入／清理与原件守卫闭合；Linux 兼容说明如实未验。最终候选、提交和本地集成身份可复核，明确披露 `EX-AUDIO-NUKED`。

上述必要游戏门缺一项就不宣布整个计划完成；不承诺未经取证的自动全游戏等价或工期。F6 完成后停止，不自动扩展新功能。

## 6. 工程与取证约束

完整阶段实现／审查／验证后独立提交及本地集成，不远程 push／发布。原资源和用户档只读，写入隔离副本；来源／静态／局部原码、实际 C／正式路径、原版画面音频及历史继承分别登记。生成器不能自证，内部实验不能代签正常游戏。

Windows 使用 WGC HWND、owned 后台输入和串行进程清理。按已有授权可作一次有记录的显示恢复／临时显示需求，必要电源改动记录并恢复，同线程释放；不改混音器、不抢前台、不循环唤醒。其它平台维护 PowerShell／Bash 对应说明，实际未跑如实标记。
