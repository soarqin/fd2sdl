# 开发计划：炎龙骑士团 2 SDL3 重写

本计划负责跨系统优先级，不重复维护函数逆向细节。2026-11-09 按 `c1b6598` 的通用逻辑完整性审计更新后续顺序；2026-11-04 的 `e9a2d81` 及 B／A／R 历史保留原范围。通用缺口与来源见[审计矩阵](common-logic-audit.md)，战场任务见 [`battlefield.md`](battlefield.md)，音频任务见 [`audio.md`](audio.md)，共同设计约束见 [`../systems/battle-session.md`](../systems/battle-session.md)。

## 1. 目标与完成口径

长期目标仍是读取原版数据、兼容原版存档和运行期数据语义，不依赖 `FD2.EXE` 运行游戏。当前目标是：**保留已完成纵向流程与 SD 静态化历史，先补齐所有可识别的跨关通用机制及其必要证据，统一审查回归后，最后推进关卡专用逻辑与静态场景适配。**审计计划已由 `b4c4bfa` 交付并集成本地 master；2026-11-09 用户随后授权在原工作树连续实施 G1—G5，各阶段完整验证并独立提交后接下一阶段，不自动开始 S。实际进度以阶段记录和 Git 为准，不把授权或计划视为已完成。

通用机制包括领域规则、服务、执行能力及其冷流程条件／分支／顺序／等待／取消；关卡专用内容是具体地图、编成、触发绑定、剧情顺序和有证据的真正特例。flow 文件不一概归关卡专用；定义与实例的边界及状态分类见[审计 §1—3](common-logic-audit.md#1-审计范围与边界)。已支持关卡继续作为通用机制夹具，后期来源可作最小取证，不提前交付整关。

状态按两个维度登记：

- **实现状态**：未实现、部分实现、已实现且自动验证通过。
- **原版验收**：已有静态／局部执行证据、待原版对照、对照通过。允许在独立副本上自动输入与捕获，只有列明场景、判据与证据范围的结果才能支持相应结论。

「已有模块」「快速入口通过」「有 API」均不等于正式流程可达；静态字节一致不等于全游戏语义等价。需要 DOSBox 的里程碑在缺少原版截图、存档、音频或 trace 等比对证据时只能标为「实现完成，待原版对照」，不能标为整体完成。旧「待人工对照」状态不因引入自动化而自动通过。

开发测试按当前执行平台验收；其他平台未执行不阻塞当前任务，仍维护兼容说明并如实登记未执行。当前 Windows 的 SDL 与 DOSBox 截图统一使用 WGC。当前平台的必测项及相应原版证据要求不因这项平台范围调整而减少。

## 3. 审查后补充的设计约束

| 设计缺口 | 本轮确定的处理原则 | 实施项 |
|---|---|---|
| 事件未处理仍记为 skipped，诊断日志与待演出 notice 共用有界存储 | 必需逻辑事件不能按成功跳过；必须执行／呈现的 notice 不能因日志满而静默丢失 | B0 |
| 胜利、失败都返回 `COMPLETE`，应用层统一回标题 | 扩展现有结果分派，保留胜／败、游戏内离场、宿主关闭和错误的区别；快速检查与真实战斗结果分开 | B1 |
| 玩家动作尚无完整提交／取消／资源消耗契约 | 查询和预检不改持久状态或 RNG；确认后的效果与资源消耗按原版顺序提交；提交后失败不能伪造整步回滚 | B0、B2、B3 |
| AI 已有效果被误当作玩家命令已完成 | 复用 effect／范围能力，不复用 AI 的候选评分、MP 门或 common tail 冒充玩家语义 | B2、B3 |
| 快照、手工槽与 runtime 容量／恢复边界不同 | 活动快照与四槽独立；保留未知字节；不截断单位；不向原版格式增加 RNG checkpoint 或 UI 状态 | B1、B5 |
| 结果门、剧情退出标志、转场和下一关初始化混在同一「完成」概念中 | stage handler 解释本关脚本；应用层编排后续流程；先做 stage 0 → 1 的可验证纵向流程 | B5 |
| 演出可能重复结算，解析失败被笼统视为可降级 | 逻辑只提交一次，演出消费已确定结果；损坏资源与主动无演出模式分开处理 | B6 |
| 原有音乐后端缺少正式场景编排 | 应用层持有 BGM，战场只在已确认的场景／phase 边界发起切曲，不让绘制或音频回调推进战场；本轮已接入，保真另验 | A5 |

这些是实现契约，完成状态以对应工作包为准；B0 错误边界、B1 结果分派和结束回合已接入，待证据菜单入口单列限制。接口、状态所有权、提交边界和失败行为统一见 [`../systems/battle-session.md`](../systems/battle-session.md)。不为落实契约先搭建通用事务框架、事件总线或脚本 VM。

R1 后新增的长期约束见[静态数据层与事件流程计划](static-data.md)：不可变定义及事件触发、条件、分支、顺序和动作编排进入可修改的冷数据；代码提供有限领域执行能力，运行单位、库存、选择、完成位与执行进度保留现有热状态 owner。不能仅搬参数或以整段 native handler 代替流程数据化；已有 DAT 定义保持唯一来源，SAV 中有效运行值和未知字节继续保留。

各 G 编号为 B3／SD1 级完整交付与提交单元，不拆函数或微步骤提交、不逐步骤等「继续」。阶段内仅测新增、改动与直接受影响路径，包含对应原版代表性验收；G5 统一审查并全面复测已支持历史功能，修复和精简后提交。SD1—SD3 自身已完成历史门保留；本次计划修订不运行全套实机回归。冷定义、有限领域执行器、现有热状态 owner／SAV／RNG 边界继续有效，不建通用 VM、事件总线或重写热系统。

### 通用阶段完成门与残余

完整门见[审计 §6](common-logic-audit.md#6-从通用机制进入关卡专用工作的完成门)。进入 S 前必须同时满足：所有已识别跨关机制含正式入口和必要呈现已验；全部来源未知项均有可追溯归属；没有未审计或未决的通用服务／规则；必要错误、取消、费用、RNG、状态、存档和 owner 通过；G5 全历史审查回归完成。一个接口、单测、某关通过或灰掉所有未覆盖能力均不足以过门。

S 残余只允许有来源理由的关卡实例／特例及明确声明不在领域完整结论内的精度／平台测量。完整波形、严格 PIC／绝对时序、物理拔插、运行时 BSS 等未验仍按原范围登记；Nuked 原始响度／音色是用户选择，不能把其余未验说成接受或通过。影响业务、共享 RNG 写序和必要可见反馈的问题仍阻塞对应 G 包。此门不承诺未取证的全游戏绝对完整。
