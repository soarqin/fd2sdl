# 开发计划：炎龙骑士团 2 SDL3 重写

本计划负责跨系统优先级，不重复维护函数逆向细节。2026-11-04 按审查与原版字节复核重新编排，代码基线为 `e9a2d81`。战场任务见 [`battlefield.md`](battlefield.md)，音频任务见 [`audio.md`](audio.md)，共同设计约束见 [`../systems/battle-session.md`](../systems/battle-session.md)。

## 1. 目标与完成口径

长期目标仍是读取原版数据、兼容原版存档和运行期数据语义，不依赖 `FD2.EXE` 运行游戏。近期目标改为：**先保证第一关受支持流程的错误、事件、胜负与保存恢复语义明确，再补玩家指令和成长，最后接入有证据的下一关及战斗演出。**

状态按两个维度登记：

- **实现状态**：未实现、部分实现、已实现且自动验证通过。
- **原版验收**：已有静态／局部执行证据、待原版对照、对照通过。允许在独立副本上自动输入与捕获，只有列明场景、判据与证据范围的结果才能支持相应结论。

「已有模块」「快速入口通过」「有 API」均不等于正式流程可达；静态字节一致不等于全游戏语义等价。需要 DOSBox 的里程碑在缺少原版截图、存档、音频或 trace 等比对证据时只能标为「实现完成，待原版对照」，不能标为整体完成。旧「待人工对照」状态不因引入自动化而自动通过。

开发测试按当前执行平台验收；其他平台未执行不阻塞当前任务，仍维护兼容说明并如实登记未执行。当前 Windows 的 SDL 与 DOSBox 截图统一使用 WGC。当前平台的必测项及相应原版证据要求不因这项平台范围调整而减少。

本轮已关闭的具体缺陷：归档读到 payload、RLE 超行／截断假成功、标题 slot 尺寸与 SDL 初始化错误路径、战场错误返回假完成、菜单静止坐标和动画高亮偏差、验证器忽略 BSS、发布清单过期。不再把这些修复重新安排为开发阶段。

历史 Linux 基线为 **29/29 CTest、39/39 Python、28/28 sanitizer 非窗口测试通过**；这不是未来固定测试数量，也不是原版验收结果。历史输入端到端测试依赖 Linux/X11、Xvfb 和 XTest；当前 Windows 原生窗口测试与原版自动比对见[图形自动化测试](../tools/gui-testing.md)，不能因窗口测试未注册仍声称完整通过。资源相关测试继续依赖本地原版文件。历史证据范围见 [`../reverse-engineering/ida-bytecheck-9.5.md`](../reverse-engineering/ida-bytecheck-9.5.md)。

## 3. 审查后补充的设计约束

| 设计缺口 | 本轮确定的处理原则 | 实施项 |
|---|---|---|
| 事件未处理仍记为 skipped，诊断日志与待演出 notice 共用有界存储 | 必需逻辑事件不能按成功跳过；必须执行／呈现的 notice 不能因日志满而静默丢失 | B0 |
| 胜利、失败都返回 `COMPLETE`，应用层统一回标题 | 扩展现有结果分派，保留胜／败、游戏内离场、宿主关闭和错误的区别；快速检查与真实战斗结果分开 | B1 |
| 玩家动作尚无完整提交／取消／资源消耗契约 | 查询和预检不改持久状态或 RNG；确认后的效果与资源消耗按原版顺序提交；提交后失败不能伪造整步回滚 | B0、B2、B3 |
| AI 已有效果被误当作玩家命令已完成 | 复用 effect／范围能力，不复用 AI 的候选评分、MP 门或 common tail 冒充玩家语义 | B2、B3 |
| 快照、手工槽与 runtime 容量／恢复边界不同 | 活动快照与四槽独立；保留未知字节；不截断单位；不向原版格式增加 RNG checkpoint 或 UI 状态 | B1、B5 |
| 结果门、剧情退出标志、转场和下一关初始化混在同一「完成」概念中 | stage handler 解释本关脚本；应用层编排后续流程；先做 stage 0 → 1 的可验证纵向流程 | B5 |
| 演出可能重复结算，解析失败被笼统视为可降级 | 逻辑只提交一次，演出消费已确定结果；损坏资源与主动无演出模式分开处理 | B6 |
| 音乐实现已有，但正式战场没有曲目编排 owner | 应用层持有 BGM，战场只在已确认的场景／phase 边界发起切曲，不让绘制或音频回调推进战场 | A5 |

这些是实现契约，完成状态以对应工作包为准；B0 错误边界、B1 结果分派和结束回合已接入，待证据菜单入口单列限制。接口、状态所有权、提交边界和失败行为统一见 [`../systems/battle-session.md`](../systems/battle-session.md)。不为落实契约先搭建通用事务框架、事件总线或脚本 VM。

## 4. 新优先级与依赖

优先级唯一来源是本节。B 项的详细工作包在战场计划，A 项在音频计划；它们不再各自维护相互冲突的「最高优先级」。

| 优先级 | 工作项 | 硬依赖 | 可验收交付 |
|---|---|---|---|
| P0 | **B0：必需事件、提交与失败边界** | 现有基线 | 未知必需 handler／事件容量不足明确失败；取消、提交前拒绝不改状态或 RNG；提交后失败不重试、不假成功 |
| P0 | **B1：第一关正式控制与结果分派** | B0 | 胜／败单独返回；结束回合连接真实后端；存取、游戏内离场、宿主退出均可由正式输入路径到达；待证据的入口单列阻塞 |
| P1 | **B2：玩家法术** | B0、B1 的动作／结果契约 | 列表、施法中心、目标过滤、取消、MP 与结算按原版证据连接现有效果；未知法术不启用 |
| P1 | **B3：玩家物品与已确认库存操作** | B0、B1 的动作／结果契约 | 列表、目标、消耗／非消耗及 slot 更新；逐分支保留原版 RNG 与取消行为 |
| P1 | **A5：战场音乐与恢复边界** | B0、现有 A4 | stage 曲目、phase primary/alternate、加载与离场的曲目／bus 生命周期；可与 B2/B3 独立推进 |
| P1 | **B4：经验、升级与持续单位状态** | B0 的提交／奖励边界；覆盖已开放指令 | 依据证据接入经验归属、升级／重算和已确认装备变更；不以新建构造器覆盖存量单位 |
| P1 | **B5：第一关结算到下一关** | B1、B4；场景音乐接 A5 | 本关专用结果回调、剧情、转场、stage 1 初始化与受支持存档恢复；不是简单 `stage++` |
| P2 | **B6／A6：FIGANI 与动态战斗音效** | B0/B1 的提交／场景契约；对应效果已实现 | 攻击／受击／施法演出与无演出模式逻辑结果、RNG 一致，动态 bank 生命周期安全 |
| P2 | **B7：后续关卡、特殊 handler 与辅助页** | 各自依赖的基础任务 | 按关卡逐项开放；若某 handler 是 B1/B5 场景必经项，立即提升到对应里程碑前置 |
| P2 | **A7／A8：声音保真与设备生命周期** | 现用音频基线；相关场景已可达 | 原版捕获、场景时序、失焦／设备恢复和对应平台验证 |
| P2 | **R1：发布与平台验收** | 拟发布支持范围及相关功能门 | 当前发布平台实机、无资源／无设备失败、第三方许可与项目 LICENSE、原版资源不分发；未验收平台不声明为已通过 |

默认实施顺序为 **B0 → B1 → B2 → B3 → B4 → B5 → B6**。表内细分契约可单独验收，不要求先完成整个 B1 辅助页集合；B4 公式可先行研究，FIGANI 也不以 stage 1 初始化完成为技术前置。A5 不等待 FIGANI，B7 不是把场景必需逻辑无限延期的容器。新增发现按「是否影响现有数据／状态正确性、是否阻塞当前场景」调整位置，不按函数大小或文件行数排序。

## 5. 验收与证据工作

| 项 | 当前状态 | 所需证据及阻塞范围 |
|---|---|---|
| V0：静态 LE／IDA 字节基础 | 已通过 | 只有输入、loader、parser 或导出流程变化时重跑；不再为新增 UI 重建整套逆向基线 |
| V1：可玩流程与原版行为 | 待原版对照，允许自动验证 | 在独立副本中自动复现菜单／结束回合、Save/Load、胜败与离场、法术／物品，保留截图、操作结果、存档或捕获并按确认判据比对；缺项阻塞对应原版行为验收 |
| V2：严格运行时对象字节 | 未通过，需新转储 | 新运行的 selector、object base 与完整 dump；21 个历史 BSS/stack 非零字节不能自动豁免。阻塞严格运行时通过声明，不阻塞已有静态证据支持的 SDL 逻辑开发 |

每个新功能同时满足：

- 逆向证据可追溯到 canonical VA、调用者及数据；新语义按 `AGENTS.md` 更新命名输入并重新生成，不手改生成伪 C。
- 无窗口测试覆盖成功、非法输入、取消、重复确认、边界值、RNG 次数和错误状态；涉及文件写入时覆盖原档不变与未知字节保留。
- 正式用户路径有输入集成测试；不能只靠 `*-once` 或直接调用 `field_game` 证明可达。
- 交互／视听行为单独完成 DOSBox 原版对照，可自动输入、捕获与比较；缺失时保持「待原版对照」，不以进程退出或运行时长代替行为判据。

命令统一引用 [`../tools/README.md`](../tools/README.md)，不在多份计划中复制一套易过期的工具操作。资源依赖、窗口依赖和未执行的平台必须分别报告；其他平台未执行不阻塞当前平台验收，当前平台缺资源、跳过或未注册的必测项仍不能声称完整通过。

## 6. 不再采用的安排与待决事项

- 删除旧的「17 个工作日」总估计。先确定每个工作包的证据、支持分支和验收样例，再估算；没有可复现场景或平台条件的项目不能承诺完成日期。
- 不重做窗口、解包、基础单位构造、存档 codec、音频队列或音乐后端选型；不将 FIFO 作为现行输入设计，详见 [`../systems/input.md`](../systems/input.md)。
- 不一次开放全部 stage，不用通用全灭条件替代私有脚本，不先造通用剧情解释器；按已证实的 stage/action 逐项实现。
- 不为拆大文件而拆文件，不添加鼠标操作、资源转换分发、通用插件或多后端选择框架。
- `FD2.TMP` 是原版运行期 sprite cache；SDL 已直接使用 FDICON 重建对应缓存语义。是否还需输出可交给 DOS 原版使用的 `.TMP` 文件，应在 R1 明确兼容范围，不把「无需运行期 TMP」误写成「所有 TMP 文件互操作已验证」。
- 项目顶层许可证和发布时的 LGPL 源码／链接义务仍需明确；已有第三方组件选择不等于发布合规已经完成。R1 的 P2 是开发排期，不是允许绕过的发布门，任何对外发布都必须先满足对应平台与许可要求。
