## 1. 尚缺什么，已经知道什么

| 性质 | 现有结论 | 不得作出的结论 |

| Q 后实际字节 | 部分字节有当前调用的 target count、菜单或物品 scalar 写入，见[调用合同](f1-defeat-caller-contracts.md)及本地独立复审 | 超过 collector 的 K 条就一定未初始化／越界 |

| 返回后消费 | 已定位掉落、AI 后续及特定胜利后main分支的条件性传值；18 个 result 入口的 incoming 寄存器性质已核清。Town0先续战斗，须到后来未覆盖EDI的终端分支才可区分 | 所有正常游戏中都能触发这些条件，或已有自然反例 |

| 尚缺证据 | 各真实调用类别的 Q／K 联合条件、合法正常状态覆盖，以及可能改变可观察行为的后续链 | 参数化文案、C 自测或某个未崩溃样本已经替代全域资格 |

旧失败、撤回建议与来源身份继续保留。[诊断页](f1-blocker-diagnostics.md)记录模型轮次错误，不作为整项目停工条件，也不代表工具通道封锁或支持已解除限制。被拒的原字节证明不重派，不改措辞／模型／供应商／工具试探。

## 2. 实际依赖

| 阶段 | 可以独立实现、验收的机制 | 必须由专项补齐的相关轨迹 |
|---|---|---|
| F2 | 启动 rand／共享 RNG 初态及推进；BIOS 时钟换算；FIFO／映射／typematic；正常等待和取消的共享接口 | 可疑动作之后额外清键、等待、RNG 调用及相位；不能用机制单测签这些整链 |
| F3 | 构造保留字节、Load raw2、存档容器、已知玩法／剧情与 owner 修复 | 死亡／掉落／经验、AI 继续、剧情尾写及 victory28 后的后续动作、胜败和离场 |
| F4 | 解码、页／mask、palette／水色／嘴型、已知第31锚别名及动作共享呈现 | 因队列或后续分支不同而改变的对象、帧序及镜头；不要求复制无业务意义的宿主栈布局 |
| F5 | PCM／音乐调度、资源、混音及设备清理 | 受相关游戏分支影响的 cue 次数、顺序及时间；Nuked 例外不豁免这些差异 |
| F6 | 全历史复审及其它已满足前置的检查 | QK 行为门必须明确通过、由充分独立证据替代内部证明，或真实保留阻塞；未闭合不得宣布全计划完成 |

依据是当前 `field_rng`／`input`／时钟接口不读取 collector 栈；启动初始化在进入这些动作之前。`field_defeat_flow.h`、`field_loot_flow.h`、Game 的动作提交和 `main`／`app_flow` 才消费死亡与后续分支。因此延期的是特定调用链的联合资格，而不是共享时钟、解码或音频后端的开发权限。

## 3. 无需新增逆向的行为验证

先用小规模代表证明方法能比较，再扩展真实相关的边界。复用项目现有 owned 输入、WGC、原版比较及 SAV 读取工具；不另建全游戏模拟器。

1. 只读核候选存档的原始来源、原版实际保存记录和游戏状态合法性。原资源／用户档不改；两端各用隔离副本。历史受控 HP／人数／事件位修改夹具不自动成为本专项合法输入。
2. 两端从同一已知合法状态开始，使用同一正常菜单、移动、物理／法术／物品或 END 操作。记录输入投递与实际业务响应；不修改二进制、寄存器、返回地址、HP、人数或掉落数据制造边界。
3. 覆盖动作前、死亡／消失、每段掉落／经验／剧情等待、返回浏览、下一动作、至少一个 END，以及 Save→Load→后续动作。需要区分的离场／胜利链再覆盖 LEAVE、准备与标题去向。
4. 用已知 SAV 格式比较完整 22,987 字节及解释字段，核单位数量／身份／HP／flags／库存／经验／事件位／回合。不可保存的中间状态使用已有画面／业务响应佐证，不能只比较末帧或“未崩溃”。WGC 图像原件及动画阶段分别保留；RGB／相位未对齐时注明原因，不暗加容差。
5. RNG 能由已对齐的启动与相同操作轨迹匹配时比较逐次结果。合法存档未包含 RNG 或实际时刻无法重合时，保留输入、重复次数、每次结果与分支，分账重复／配对的局限；统计相近不能替代精确共享 RNG／时序门。必要的未验项继续留账。

允许复用已有合法存档、数据格式、来源报告和已知观察点；不重新做被拒的原栈实验。方法若无法独立观测某内部形式，不声称已证明它；只评估该形式是否会改变必须满足的游戏合同。

## 4. 代表族与覆盖资格

| 代表族 | 最小方法试运行 | 后续必须覆盖的差异 |
|---|---|---|
| 玩家／AI 物理 | 一次正常攻击或反击、确有死亡／掉落的完整后续链 | 不同调用者、取消／失败、后续 actor 和 acted 状态 |
| 法术／物品 | 正常多目标效果、完整掉落／经验和下一回合 | 正常可达的多掉落 K、屏内 D、无掉落但多人消失；不能用 API 容量替代边界 |
| 状态／剧情尾写 | 正常 END 状态变化或已知合法剧情触发 | 阵营、最后镜头、剩余掉落、事件位及结果优先序 |
| 胜利／后续生命周期 | 现有合法胜利链接准备／下一战 | 特定胜利后的后续动作、存取、离场和标题／退出去向 |

代表共用资格须有相同 producer、调用时点、反馈与后续 consumer 的依据。其它绑定通过全量数据／参数检查加入覆盖表，不按重复引用数计功能率。尚无合法状态或操作路径的边界列为缺夹具／可达性证据；不能因为难以构造而排除，也不能伪造非法状态。

## 5. 完成门及重新检查条件

专项收据逐行映射原缺失性质、相关正常参数域、可观察合同、独立来源、实际运行、继承及限制。至少包括：

- 已知条件性表达差异有对应实现／无影响证据，不把源码形式不同直接称为功能错误。
- 相关正常域有可达见证、独立包含关系或确切的来源排除；高 K／D 未验证不默认为不可能。
- 保存／恢复、后续动作与多回合、输入消费、RNG、FX 和 cue 的受影响部分逐项闭合；未知语义或必需证据仍缺则最终门不通过。
- 内部字节／寄存器性质若不再作为验收手段，须明确标为“内部性质未验，功能合同由以下独立证据覆盖”，逐项解释替代充分性；不能改名为原形式证明通过。

凡修改死亡筛选／提交、collector／掉落／库存／经验、AI 后续、剧情／胜利／离场、Save／Load，以及相关清键／等待／RNG／FX／cue 时，重跑直接受影响的代表并更新覆盖。仅文档、无语义注释或无依赖模块变更不重放全部历史 GUI。F6 最终统一审查、修复精简与历史回归仍执行。
