## 本轮审查结论与后续

已实现 B1 子阶段审查发现并安排修复：runtime 单位区 64 条与存档格式 96 条边界混用、首次保存不能创建活动文件、错误重建坏档会覆盖其他槽，以及外层 runner 超时绕过子进程清理。修复按所属小阶段提交；窗口清理采用原生 Job，删除未使用的旧截图热键分支。未为这些修复新增场景框架或另一套存档 codec。

真实 `START.SAV` 的 active／roster 数为 12／4，后期本地档为 27／31，推翻旧 count-copy 假设。B1.2b 因此增加独立 roster owner、原版构造与招募事务，收回不正确的手工 Load 活动恢复；该路径等待 B1.4 的真实关卡重建。审查又修复了已恢复的 raw roster 尾在跨文件保存时丢失的问题，使用整表 owner 并删除旧活动表手工恢复分支。以上是有原版数据和调用链依据的计划调整，无待用户选择的业务分歧。

接下来的窗口工作为 B1.3a：肯定 END 一次，识别新回合及其默认焦点，再从正式菜单 Save，比较已确认且不依赖随机流的字段。未对齐的伤害、AI 路径与镜头不作为一致性通过判据。原版肯定 END 与 Save/Load 的剩余路径、march、总览、辅助页及四槽入口仍分别登记；允许 B2 预研，不将 B1 整包记为完成。
